# MATCHING RULE (as for jaq). A line matches an LLVM function whose
# demangled v0 name is equal to the line, or continues with `::<` (any
# generic instantiation), or continues with `::{closure` (a closure defined
# in it). So `zopfli::lz77::find_longest_match` does NOT match
# `zopfli::lz77::find_longest_match_loop`, and `zopfli::squeeze::lz77_optimal`
# matches its `::{closure#0}` but NOT `lz77_optimal_run` or
# `lz77_optimal_fixed`. Lines whose first non-space character is `#` are
# comments. Names were copied from `scripts/perf_hotness.py --inline`
# output (llvm-symbolizer), with the generic `::<...>` suffix cut off.
#
# HOW THEY WERE CHOSEN. The rule in section 1 of jev-marks.rationale.md,
# written before the tables were read: rank by perf reach on the search set
# (search-*.dat, recorded as train-*.data), add in rank order, stop once the
# union covers >= 90% of in-binary user cycles. `perf record -e cycles:u
# -F 5000`, 6 runs per case, on the plugin-off base build
# target-zopfli-sites-base (normalised-code identical to Stage 0).
# Per mark below: self and reach on the search set (summed periods), the
# per-case reach (binary/json/text), and the holdout values.
